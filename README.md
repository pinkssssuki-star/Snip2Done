# 记忆面板（remeber-er）

> 看到以后要处理的东西，按 `Ctrl+Shift+A` 截下来，做**一次**情感判断 —— 这是 **Todo** 还是 **Wantdo** —— 然后它就一直挂在你桌面上。
>
> **Todo** 被 DDL 催着走；**Wantdo** 靠你的注意力续命：你不碰它，它就慢慢变淡，最后滑进 Paper Plane Bin，但永远能捞回来。

一个常驻桌面的半透明小面板。**截图不是待办，是记忆钩子。**

当前版本 **v0.9.1**。改过什么、为什么改、怎么验的，都在 [`CHANGELOG.md`](./CHANGELOG.md)。

## 仓库结构

```
native/      ← ★ 主版本。纯原生 WPF/XAML，开发都在这里
legacy/      ← 旧版本，留着存档，不再改动
docs/        ← 设计稿、打包说明、给朋友的话、实测报告
```

| 目录 / 文件 | 是什么 | 状态 |
|---|---|---|
| **`native/`** | 纯原生 WPF/XAML。1 进程 / ~110 MB / 0.14 MB 分发 | **★ 主版本，后续只改这里** |
| `legacy/electron/` | 最初的 Electron 版（HTML/CSS/JS） | 存档。功能最全的上一版，参考用 |
| `legacy/wpf-webview2/` | 中间实验：WPF 套 WebView2 复用 HTML UI | 存档。结论是这条路不划算，见实测报告 |
| [`CHANGELOG.md`](./CHANGELOG.md) | **改过什么、为什么改、怎么验的** | 每次改动都往里加 |

一次技术选型的结论（完整数据见 [`docs/WPF-WebView2实测.md`](./docs/WPF-WebView2实测.md)）：

| | Electron | WPF + WebView2 | **纯原生 WPF** |
|---|---|---|---|
| 分发体积 | 98.5 MB | 0.94 MB | **0.14 MB** |
| 进程数 | 5 | 7 | **1** |
| 总工作集 | 419 MB | 653 MB | **~110 MB** |
| 面板首帧 | 330–410 ms | 2800–3100 ms | **~630 ms** |
| 截图抓屏 | 357–476 ms | 26–38 ms | **28–38 ms** |

WebView2 那条路被实测否掉了：它省掉的是「安装包里的 Chromium」，省不掉「跑起来之后的 Chromium」，内存和启动两个关键指标都比 Electron 还差。

## 快速开始

```
双击  native\启动-原生版.cmd
或    powershell -ExecutionPolicy Bypass -File native\run.ps1
```

`out/` 不入库，所以第一次跑（或 clone 之后）启动器会**自动先编译一遍**。

**要求**：Windows 10/11 + .NET Framework 4.8（系统自带）。**不需要** .NET SDK —— 编译走 VS 2022 的 MSBuild + 一份从 NuGet 取来的参考程序集，`build.ps1` 会自动处理。

面板出现在屏幕右下角。进面板后：

1. 按 `Ctrl+Shift+A` 截图 → 拖框选区 → 点框右下角的 **✓**（或按 `Enter`）→ 选 Today / 两三天 / Wantdo
2. 右上角 **⚙** → 「**试试让时间以 30000 倍流逝~**」，会自动切回主视图开始演（约 1 分钟）
3. 看 Wantdo 磁贴在你眼前一点点变淡，然后逐个掉进纸篓
4. 点开一张 = 看它一眼 = **续命**；按 ✕ = 主动放下，进 Paper Plane Bin
5. 点「Paper Plane Bin」→ 点它 → **捞回来**

```powershell
powershell -File native\run.ps1 -Bench -Primary   # 跑基准测试（内存/启动/截图延迟）
powershell -File native\run.ps1 -View set         # 启动时直接进某一页
powershell -File native\build.ps1                 # 只编译
```

## 快捷键

| 按键 | 作用 |
|---|---|
| `Ctrl+Shift+A` | 截图捕获（主入口） |
| `Ctrl+Shift+H` | 显示 / 隐藏面板 |
| `Ctrl+Shift+Q` | 退出 |
| 框选层：`Enter` | 确认选区（等价于点 ✓） |
| 选择器：`1` / `2` / `3` | Today / 两三天 / Wantdo |
| **两三天**旁边写天数 | 留空 = 随机 48~72 小时；写 `5` = 5 天后（标签也会跟着显示「5 天」） |
| `Esc` | 取消当前这一步 |

## 两个房间的规则

| | Todo | Wantdo |
|---|---|---|
| 长什么样 | 清单行（勾选框 + 标题 + 小缩略图） | **图片磁贴**（大图 + 来源 + 生命条） |
| 驱动力 | DDL 压力 | 注意力衰减 |
| 会不会变淡 | **永远不会** | 会，不碰它就淡 |
| 终局 | 完成 / 逾期 | 完成 / 淡出→Bin / 主动放下 |

**高度按「露出行数 × 行高」分配**：默认 `4 × 52px : 1 × 112px`，两块各自内部滚动，窗口拉大时按同一比例等比扩展 —— 所以 Todo 再多也不会把 Wantdo 挤没。

## 交互细节

| 动作 | 结果 |
|---|---|
| 截图后 | 弹出归类窗，**标题已预填窗口标题并选中**，可直接改、可删空（删空就回落成窗口标题） |
| 框选 | **每块屏都会铺一层**，在哪块屏上拖就在哪块屏里选（单块屏内跨屏拖拽不支持，见下） |
| 框选之后 | 选区**不会消失** —— 可以拖角微调、拖内部平移；确认键是选区外侧的**黑底白勾**那个小方块 |
| **快速模式**（设置里打开） | 松开鼠标即定，跳过确认那一步。`一框，一分类` |
| 顶栏 **⇧** | **窗口置顶开关**。单屏用户不想被一直压着的时候可以关掉（状态会记住） |
| 顶栏 **▾** | 折叠成一条，只留顶栏。**原地缩放**（位置一个像素都不动），宽度是量着顶栏实际需要定的，不会把按钮挤变形 |
| **把面板拖出屏幕边缘** | 松手就**贴边隐藏**：边上只留一条窄边 + 一个紫色抓手。鼠标移上去滑出来，移开再滑回去；拖回屏幕中间就取消 |
| 顶栏 **＋** | **手动记一笔**（不截图也能记）。写完点输入框右边那个紫色 **+**，或者按 `Enter`；**加完自动收起** —— 没人会连着录好几条 |
| 详情窗里的 **+** | 这条没有截图时，中间那块空位就是一个大的「**补一张截图**」；有图时右下角有小加号可以换图。走的是和截图主流程**同一套框选层** |
| **点 Todo 整行** | 打开详情；若是已完成的，再点一下会**像泡沫一样消散**，收进完成列表 |
| 点 Wantdo 磁贴 | 打开详情：窗口**按图片比例自适应大小**，可改标题、写备注（自动保存）；有 **Get Done** 按钮 |
| **在一个条目上停约 0.5 秒** | 面板左侧弹出**放大预览**，不点进去就能看清图里记了什么 |
| 条目没有标题时 | 界面留空，不写「（没有标题）」这种占位文字；meta 行会补上来源 |

> **跨屏框选**：现在每块屏各有一层（各铺自己那块屏的截图），所以「主屏按键、副屏框选」是可以的。
> 但一次框选**不能跨过两块屏的边界** —— 混 DPI 下一条窗口跨屏没法同时正确渲染。
> 要支持的话得改成「一整张虚拟屏位图 + 单窗口」，代价是副屏会被缩放变糊。

## 完成 vs 纸篓：两条完全不同的路

这是这个产品最容易被做错的地方 —— **完成不是丢弃**。

| | 完成（Done） | 纸篓（Paper Plane Bin） |
|---|---|---|
| 怎么进去 | Todo 勾选 / Wantdo 点 Get Done | 点 ✕ 主动放下，或 Wantdo 长期不碰自动淡出 |
| 含义 | 了结、有成就感 | 「暂时放下」，不算失败也不算完成 |
| 去哪 | **完成列表**，分 `Todo` / `WD` 两个标签 | 纸篓，分 `使命 Todo` / `初心 Wantdo` 两个标签 |
| 会记录 | 完成时间、**完成时长**、心得 | 在纸篓里待了多久、进出过几次 |

**Todo 永远不会因为你不看它就进纸篓。**

### 纸篓里的两个分区（性质相反）

| 标签页 | 里面是什么 | 能做什么 |
|---|---|---|
| **使命 Todo** | 你主动点 ✕ 舍弃的、有 DDL 的事 | **不能捡回来** · 顶部「倒垃圾」一次清空（点第一下变「确定清空？」，第二下才真删） |
| **初心 Wantdo** | 长期不碰、自己淡进来的念想 | 点一下捡回来 · **永远不删**，就陈列在那儿当提醒 |

区别是刻意的：**Todo 的舍弃是「这件事我不要了」，允许彻底清掉；Wantdo 的淡忘是「我当初想要过这个」，留着照你。**

「倒垃圾」是整个程序里**唯一不可逆**的操作 —— 别的都能反悔，所以它必须点两下。

### 完成列表（TODO 标题栏右边的 `Done N`）

按**完成日期**分组（今天 / 昨天 / 前天 / x 月 x 日 · 周几），每条显示 Todo / Wantdo 标签、缩略图与标题、**用时**与完成时刻。点任意一条 → 打开**完成记录**。

### 完成记录

**写心得**（点 Get Done 时）：显示「记于 / 到目前为止 / 你看过它 N 次」，下面是心得输入框。

**回看**（完成后点开）：一句话总结（「你把它记了 **11 天**，看了 **5** 次，最后写下 **70** 个字。」）+ 心得原文 + **小结**（从记下到完成 / 完成于 / 你看过它几次 / 最后一次看它 / 心得字数 / 平均多久看一次 / 在纸篓里待过多长时间）。

> 最后那条刻意不做成「失败记录」。被放下过又捡回来的东西，本来就是这个产品的正常形态。

## 设置页（⚙）

| 项 | 范围 | 说明 |
|---|---|---|
| **快速模式** | 开 / 关 | **默认关**。打开后框选松手即定，不用再去点右下角的 ✓ |
| **开机自启** | 开 / 关 | **默认关**。写 `HKCU\...\CurrentVersion\Run`，**不需要管理员**。开关状态直接读注册表真实值 —— 手动删掉或把 exe 挪了位置，开关会自动变回「关」，不会骗你说已开启 |
| **隐藏折叠按钮** | 开 / 关 | **默认关**。把顶栏的 ▾ 收起来（有侧边收起了，折叠基本多余）。**已经折叠着的时候它还会留着** —— 不然你就展不开了 |
| **演示加速** | 按钮（不是开关） | 在设置页，不在顶栏。点「试试让时间以 30000 倍流逝~」开始一次约一分钟的演示：Wantdo 在眼前变淡、逐个掉进纸篓，跑完**数据原样还给你**。**第一次**会顺手把所有 Wantdo 的生命复原（「这次我帮你把 WantDo 全都注意了一遍噢~ 下不为例~」），以后就不帮了（「这次不会帮你了噢~」）。中途可以「停下」，同样会还原 |
| 面板透明度 | 30% – 100% | **默认 80%**。只影响面板底色；**条目卡片始终不透明**，保证任何桌面背景下都读得清 |
| Wantdo 保护期 | 1 – 60 天 | 默认 7 天，这期间完全不衰减 |
| 多久后放手 | 2 – 180 天 | 默认 21 天，超过就滑进 Paper Plane Bin（随时能捞回来） |

后两个数字**只影响 Wantdo，Todo 永远不受影响**。改完立刻生效并持久化。

**窗口置顶**不在设置页，在顶栏那个 **⇧** 按钮上 —— 它是要随手切的，藏进设置里反而麻烦。状态存在 `settings.alwaysOnTop`。

### 单实例

**一份用户会话只允许跑一个面板。** 再点 exe 不会开出第二个，而是把已有那个叫到眼前（贴边藏着就滑出来、隐藏了就显示）。

不这么做的话第二个实例是个僵尸：窗口在、吃一百多 MB，但**全局热键抢不到**（Ctrl+Shift+H / Q 都在第一个手里），于是第一个一关，剩下的还杵在桌面上，而你已经没有任何键能管它；几个实例还会同时写同一份 `data.json`，后写的盖掉先写的，直接丢数据。

实现是 `Local\` 命名 mutex + 一个命名事件。判定放在**碰日志和数据目录之前** —— 第二个实例不该留下任何痕迹（连日志都不该被它清掉）。

## 设计原则（别改坏）

1. **不做 OCR，不做 AI。** 你就是最好的识别器 —— 再看见图片你自然想得起来当初为什么截它。这不是省事，是产品定义。
2. **淡出不是删除。** 初心 Wantdo 那一区永远只陈列、不删；能删的只有使命 Todo 那一区（且必须点两下）。
3. **不弹窗。** 面板常驻但不打断你；Todo 临近截止时是**它自己变色**，不是它来催你。
4. **不做全文搜索。** 没有 OCR 就没有可搜的文本，这一条是有意放弃的，不要承诺。
5. **条目卡片不透明。** 面板可以透，但条目必须永远清晰可读 —— 这是可读性底线。

完整设计说明见 [`docs/设计稿.md`](./docs/设计稿.md)。

## 技术

纯原生 WPF/XAML，**零 Chromium、零第三方依赖**。整个程序就是一个 153 KB 的 exe。

```
native/
  RemeberEr.Native.csproj   ← 经典 csproj（这台机器没有 .NET SDK，走 MSBuild + 参考程序集）
  build.ps1 / run.ps1       ← 编译 / 启动（启动器会自动触发编译）
  pack.ps1                  ← 打成发给朋友的 zip
  pack/使用说明.txt          ← 一起塞进 zip 的说明
  启动-原生版.cmd / 启动-基准测试.cmd
  src/
    Program.cs              ← 入口：DPI 感知、参数、数据目录、日志
    Interop.cs              ← 全部 Win32（热键 / BitBlt / 显示器 / DPI / 合成输入）
    Mvvm.cs                 ← ObservableObject / RelayCommand / 转换器 / DPI 换算
    ViewModels.cs           ← 面板 VM + 缩略图缓存（后台单线程低优先级解码）
    Capture.cs              ← 抓屏 / 裁剪 / PNG
    Json.cs, Store.cs       ← 数据层，和 JS 版逐字段对齐过
    Theme.xaml              ← 设计 token（照抄 panel.css）与控件模板
    PanelWindow.xaml        ← 常驻面板：主 / 纸篓 / Done / 设置 四种视图
    OverlayWindow.xaml      ← 全屏框选（拖角微调 / 快速模式 / ✓ 确认）
    ChooserWindow.xaml      ← Today / 两三天 / Wantdo + 标题
    DetailWindow.xaml       ← 看大图 + 改标题 + 写备注 + Get Done
    RecordWindow.xaml       ← 完成记录：写心得 / 回看小结
    PreviewWindow.xaml      ← 长悬停时的放大预览
  tools/get-refasm.js       ← 从 NuGet 取 .NET Framework 4.8 参考程序集
  shots/                    ← 各视图的实拍截图（验收证据）
```

数据：JSON + 图片目录，放在 **`%APPDATA%\remeber-er`**（和 Electron 版同一个目录，所以装了旧版的人打开原生版就能直接看到已有条目）。图片旁边会带一份 `<id>.thumb.png` 缩略图缓存 —— WPF 的 PNG 解码不做缩放解码，不缓存的话每次启动都要把整张截图解一遍。

日志在同一个目录下的 `native.log`（每次启动重开一份，不会越滚越大）。

### 打包发人

```powershell
powershell -ExecutionPolicy Bypass -File native\pack.ps1
# -> dist\记忆面板-<版本>-win64.zip   （约 110 KB：一个 exe + HTML 说明 + 纯文本说明）
```

版本号在 `src/Program.cs` 的 `Version` 常量里，`pack.ps1` 从那里读，不会两处不一致。打包脚本最后会自动列出 zip 内容做自检。

**没有任何运行时依赖**：.NET Framework 4.8 是 Win10/11 自带的，不需要装 .NET SDK，也不需要 WebView2。

说明文档是**从同一份内容生成 HTML 和 TXT 两份**的，不会各写各的：

```powershell
node native\tools\make-guide-data.js     # 1. 造一份「可以对外示人」的演示数据
native\out\RemeberEr.Native.exe --data=.tmp\guide-data --flow=ui --shotpad=0   # 2. 截干净的图
node native\tools\make-guide.js          # 3. 生成 pack\使用说明.html / .txt
node native\tools\check-guide.js         # 4. 检查每节的块顺序（可选）
```

> **截图必须用演示数据**（`make-guide-data.js` 造的纯渐变图 + 通用标题）。
> 用真实数据截出来的图里是你自己的桌面壁纸、浏览器标签、聊天窗口标题 —— 发给朋友等于把自己的屏泄出去。
> 截图时还会把 `panelOpacity` 设成 1.0，免得桌面从半透明面板后面透出来。

### 踩过的坑（都写在实测报告里）

- **混 DPI 双屏**：窗口建在主屏再 `SetWindowPos` 挪走，WPF 不跟这次 DPI 变化，布局坐标和鼠标坐标会差一个缩放系数。必须在窗口出生前就按目标屏 DPI 算好逻辑坐标。
- **别拿 `SystemParameters.WorkArea` 给副屏上的窗口做钳制** —— 那是主屏的工作区，副屏截完图归类窗会被硬拽回主屏。要按「截图那块屏」的物理矩形钳。
- **分层窗口在副屏上销毁会「分段消失」**：`AllowsTransparency=True` + `DropShadowEffect` 的弹窗，关掉时能看到逐段抹除；同尺寸的不透明窗口就没这问题。圆形弹窗一律走「不透明 + DWM 圆角/投影」，关之前再 `Hide()` 一次更保险。
- **`Path` 在 `Stretch=None` 下不会把几何体原点归零**：它按原始坐标绘制、布局盒却按包围盒算，于是内容整体偏移「包围盒左上角」那么多。想让它居中，包一层 `Viewbox`，别手算坐标。
- **`SetProcessDpiAwarenessContext` 会返回 False**（感知已被别的东西定死），要靠 `app.manifest` 声明 `PerMonitorV2`。
- **同步解码图片会拖垮启动**：11 张图 775ms。改成后台单线程低优先级解码 + 缩略图缓存。

## 已知问题 / 未完成

- 框选后还不支持方向键微调（拖角够用）
