## 0. 一句话定义

**看到一样以后要处理的东西，按快捷键截下来；只做一次情感判断（这是「必须做」还是「想做」），然后它就一直挂在你桌面上。**
必须做的事被 DDL 催着走；想做的事靠你的注意力续命 —— 你不碰它，它就慢慢变淡，最后滑进纸篓，但永远能捞回来。

---

## 1. 边界：它**不是**什么

先把话说死，避免越做越糊：

| 它不是什么 | 为什么不做 |
|---|---|
| **不是一个截图工具** | Snipaste / PixPin / ShareX / flameshot(30.8k★) 已经把这一层做满且免费。截图质量上打不过任何一个，不要竞争这一层。 |
| **不是「截图转待办」** | [Capter](https://capter.app) 已经在 Win + Mac + Web 三端做完这条轴：`Ctrl+PrtScrn` → 拖框 → AI 起草标题/描述/标签 → 解析 "by Friday" 成 deadline → 三时点提醒 → Google Calendar / Jira 同步，**早期访问免费**。止步于此就是它的免费克隆。 |
| **不是全时屏幕记忆** | screenpipe(21.5k★) / Windows Recall / 屏忆(1.4k★) 已占满这条赛道，且**它们索引「时刻/帧」，不索引「意图」**。 |
| **不做 OCR，不做 AI** | 见 §5。这不是省事，是产品定义。 |

**唯一的、也是足够的差异点：**
1. **捕获时由人来标注时间意图**（「必须做 / 想做」这一步）—— 20+ 个竞品里 100% 缺失；
2. **以记忆为中心，而不是以任务为中心** —— 截图是主体，不是附件；
3. **纯本地、零模型、零配额** —— 没有 API 调用，没有 20 张/天的上限。

## 2. 两个房间：需要**相反**的机制（核心设计）

两栏看起来是「同一套 UI 的两组数据」，但行为逻辑必须是对立的：

| | 必须做（Todo） | 想做（Want） |
|---|---|---|
| 驱动力 | **DDL 压力** —— 越拖越红 | **注意力衰减** —— 越不理它越淡 |
| 自动变化 | **绝不衰减**。任务不会因为你不看它就消失，它只会逾期 | **必须衰减**。这就是它自我清洁的方式 |
| 终局 | 完成 / 逾期 | 完成 / 淡出→纸篓 / 主动放下 |
| 情感基调 | 责任、紧迫 | 温柔、无罪恶感 |
| 有截图吗 | 有 | 有 |

**为什么必须分开：** 所有待办软件最后都变成一座愧疚纪念碑 —— 因为义务和愿望被塞进同一个列表，你每看一眼，那些没做的愿望都在指责你。分开之后，Todo 是债务（做不完天经地义），Want 是欲望（不做也不欠谁的）。

**这个对立本身就是设计语言：同一个界面里，左边的东西在催你，右边的东西在等你。**

⚠️ 代码里对此有硬性保证：`decay.js` 只对 `room === 'want'` 生效，`store.sweep()` 也只扫描 want。有单元测试守着（「Todo 永远不会被衰减送走」）。

## 3. 衰减机制：靠**注意力**，不是靠日历

### 判据是 `lastTouchedAt`，不是 `createdAt`

「我三周没点开它」≠「我不再想要它了」。所以衰减衡量的是**你真实的注意力分配**：

- 你**碰过**它（点开看大图）→ `lastTouchedAt` 刷新 → 满血复活
- 你**一直不碰**它 → 慢慢变淡 → 到点滑进纸篓

点开看大图这个动作本身就是「续命」，因为**看见它就是attention**。这也是产品名「看它一眼」的由来。

### 默认参数（真实使用）

| 参数 | 值 | 含义 |
|---|---|---|
| `fadeStartDays` | **7** | 头一周满血，完全不衰减 |
| `fadeEndDays` | **21** | 第 21 天降到最低可见度 |
| `minOpacity` | **0.22** | 最低可见度（再低就看不见了，所以有下限） |
| `binAfterDays` | **21** | 超过 21 天没碰 → 进纸篓 |

刻意偏慢。太快会让你每次打开都在抢救自己的愿望，那就变成负担了。**这三个数字是整个产品最需要你亲手调的东西。**

### 演示模式：约 5 分钟跑完一次完整周期

面板右上角 ⚡ 按钮打开。时间被压缩 **6000 倍**（1 天 ≈ 14.4 秒），所以：
- 第 7 天（≈100 秒）开始变淡
- 第 21 天（≈5 分钟）进纸篓

**这是这个 MVP 存在的唯一理由** —— 让你在 5 分钟内就能判断这个机制是让你觉得被解放，还是被冒犯。

### 三条不可动摇的原则

1. **淡出不是删除。** 进纸篓，永远能捞回来。
2. **纸篓里的东西不压缩成标题文本。** 捞出来的时候要连原始截图一起回来，上下文完整。
3. **文案比机制重要。** 说成「你没能坚持这个愿望」→ 摧毁动力；说成「你的注意力有限，这是它在告诉你你真正想要什么」→ 给你力量。**淡出不是失败，是筛选。**

## 4. 交互：**一次按键 + 一次情感判断**

```
看到某样东西
   ↓
Ctrl + Shift + A
   ↓
拖框选区（全屏压暗，只剩你框的那块亮着）
   ↓
      「这一张，是必须做，还是想做？」
       ↓            ↓           ↓
     今天         这几天        想做
   (一天内)     (三天内)     (无期限)
      ↓            ↓           ↓
       存入「必须做」      存入「想做」
```

**这不是数据录入，是情绪分类。** 比「选今天/这周/以后 + 填截止时间」轻太多了 —— 而且它天然不会填错，因为你比任何 AI 都清楚自己刚才是焦虑还是心动。

### 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl+Shift+A` | 截图捕获（主入口） |
| `Ctrl+Shift+H` | 显示 / 隐藏面板 |
| `Ctrl+Shift+Q` | 退出 |
| 选择器里 `1` / `2` / `3` | 今天 / 这几天 / 想做 |
| `Esc` | 取消当前操作 |

### 面板交互

- **常驻、半透明、置顶、不进任务栏**，可拖动、可折叠成一枚小胶囊
- **不弹窗提醒** —— 但 Todo 临近截止时那条自己变红/浮上来。**是它变了，不是它来打断你。**
- 点「想做」卡片 = 看一眼 = 续命；右上角 ✕ = 主动放下（进纸篓）
- 「废纸篓」里点一下就捡回来，满血复活
- ＋ 手动记一笔（不截图也能用）

## 5. 为什么不做 OCR、不做 AI

这是本项目最关键的一个决定，理由是产品观而非技术懒惰：

### 再认（recognition）远强于回忆（recall）

你不需要「想起」你截过什么，你只需要**再看见它**。**截图本身就是最好的检索键**，信息量远超任何 OCR 文本或 AI 摘要。所以「只存图片」不是妥协，是优势。

### 砍掉 AI 带来一连串连锁收益

不需要模型 → 不需要 API → 不需要账号 → 不需要网络 → **没有配额** → 没有延迟 → 数据不出本机。

Capter 那个「20 张/天」的上限**不是产品设计选择，是云端算力的成本结构逼出来的**。而本地方案**没有边际成本** —— 这是结构性的差异，不是优化出来的。

### 代价必须说清楚

- **全文搜索没了**。没有 OCR 就没有可搜的文本，这一条要主动放弃并**明确不承诺**。
- 检索维度只剩：**时间 / 来源软件 / 你选的档位 / 浮现**。
- 这也是为什么「档位」从「一个差异化功能」升级成了**整个系统的数据模型** —— 它是你手里唯一的一条「意义」。

### 唯一保留的文本：前台窗口标题

`GetForegroundWindow` + `GetWindowText`，**一次 Win32 调用，不需要 OCR**，实测约 530ms（与截图抓取并行，不阻塞）。

经常是仅次于图片本身的第二强回忆线索（「哦，是 B 站那个页面」）。这是纯图片原则下唯一不该省的字段。

⚠️ 有一个容易踩的坑：**必须在我们的 overlay / chooser 窗口出现之前采样**，否则前台窗口会变成我们自己。代码里这一点是并行采样的（`Promise.all`）。

## 6. 技术实现

### 为什么这一版是 Electron 而不是 Tauri

| | 结论 |
|---|---|
| 原计划 | Tauri 2（体积几 MB、内存低，对常驻软件是核心竞争力） |
| 现实 | 这台机器**没装 Rust**（`cargo` / `rustc` 都不存在） |
| 取舍 | **Demo 阶段优先验证设计，不验证技术。** Node 已在，Electron 一步就能跑起来；装 Rust 工具链要下载 GB 级内容，会拖住「今晚看到东西」这个目标。 |
| 代价 | 常驻内存约 200MB+（4 个进程）。对最终产品不可接受，对验证设计无所谓。 |

**关键工程决定：把会被替换的部分隔离干净。**

`src/shared/decay.js` 是**纯函数、零依赖**的 —— 整个衰减算法和存储巡检逻辑都在这两个文件里，**迁到 Tauri 时可以原样搬走**，只需要重写窗口/截图/热键这些「壳」。`store.js` 也刻意只依赖 `fs` / `path` / `crypto`（Demo 用 JSON，升级到 SQLite 只需替换这一个文件）。

### 文件结构

```
src/
  shared/decay.js          ← 纯逻辑：衰减算法（可原样迁走）
  main/
    main.js                ← 窗口、全局热键、IPC、图片协议、启动
    store.js               ← 持久化 + 衰减巡检（接口稳定，实现可换）
    capture.js             ← 抓屏 + 按 CSS 矩形裁剪（含多屏 / 高 DPI 处理）
    wininfo.js             ← 前台窗口标题（PowerShell，静默降级）
    devseed.js             ← 仅演示用：灌样例 + 手搓 PNG
  preload/{panel,overlay}.js
  renderer/
    panel/                 ← 常驻面板（两房间 + 纸篓 + 统计）
    overlay/               ← 全屏框选
    chooser/               ← 「今天 / 这几天 / 想做」三选一
    detail/                ← 看大图（= 续命动作）
test/decay.test.js         ← 16 项单元测试
scripts/shot.js            ← 开发用：只裁面板区域截图，验证 UI
```

### 数据模型

```jsonc
{
  "id": "uuid",
  "room": "todo" | "want",
  "state": "active" | "done" | "binned",
  "title": "前台窗口标题",        // 唯一保留的文本
  "source": "进程名",             // 如 Weixin / chrome
  "image": "images/<id>.png",     // 原图，永不压缩成文本
  "createdAt": 1757...,
  "lastTouchedAt": 1757...,       // ← 衰减判据
  "touchCount": 0,                // 被看过几次
  "dueBucket": "today" | "soon" | null,
  "dueAt": 1757... | null,        // 仅 todo
  "doneAt": null,
  "binnedAt": null
}
```

图片通过自定义协议 `appimg://local/<path>` 提供，**不用 file://**（避免 CSP 与同源问题）。

**完整截图链路（`Ctrl+Shift+A` → 全屏框选 → 裁剪 → 三选一 → 入库）没有被人手真正跑过一遍。**

代码路径完整，各环节的零件（抓屏、裁剪、overlay、chooser、存档）都单独验证过，但**这些零件串起来的那一次鼠标拖拽，需要你自己按一下才能确认**。这是本次交付里唯一的空白。

### 🚧 还没做

- 与应用全屏时共存（游戏 / 看电影 / **屏幕共享时的隐私保护**）
- 持续性愿望（「想学吉他」这类没有完成态的东西，不该硬塞进勾选模型）
- 提醒 / 通知
- 打包成 exe
- 纸篓里 Todo 和 Want 混在一起（Demo 里为了「永不丢数据」故意这么做的）

## 8. 怎么跑

```bash
npm install          # 已经装好了
npm run demo         # ← 推荐先用这个：带样例数据，用项目内独立数据目录
```

`npm run demo` 用的是 `<项目>/.userdata`，**不碰你的真实数据**。

## 9. 下一步：只需要验证**一件事**

> **「变淡」会让你觉得被解放，还是被冒犯？**
